# code-scenario-testcases 新增「场景类型」列 设计文档

> **日期**：2026-08-02
> **版本**：v1.19（本设计对应版本）
> **状态**：待实施

## 背景与目标

当前 skill 生成的用例 Excel 已按「判定点分支」覆盖成功与失败路径，但主 sheet **没有显式的「正常/异常」标识**——每条用例是正常路径还是异常路径只能靠读「预期结果」推断。目标：让 skill 明确体现「新增用例场景（正常场景 + 异常场景）并显示在 Excel 中」这一能力——**为每条用例标注「场景类型」（正常流程 / 异常流程）**，使"每个业务场景天然覆盖正常流程 + 各异常分支"在 Excel 中一目了然、可筛选、可核算。

## 设计方案

### 1. 主 sheet 新增「场景类型」列（14 → 15 列）

- 位置：**第 5 列，紧邻「用例名称」之后**
- 新列顺序：
  `用例编号 / 业务场景 / 功能 / 用例名称 / 场景类型 / 验证点 / 前置条件 / 操作步骤 / 验证方法 / 可自动化程度 / 优先级 / 预期结果 / 测试结果 / 备注 / 代码位置`
- 值枚举：`正常流程` / `异常流程`（下拉可选，避免手写错别字）
- `cases.json` 对应字段：`scenario_type`（键名与 `scripts/generate_excel.py` 的 `COLUMNS` 一致）

### 2. 场景类型判定规则（按路径最终现象分类，不看分支方向）

| 分类 | 定义 |
|---|---|
| **正常流程** | 该用例路径**最终成功完成功能**：校验通过、成功返回、状态变更成功、页面正常展示 |
| **异常流程** | 该用例路径**最终被拒绝/失败**：抛异常、返回错误码/文案、状态不可达拒绝、外部依赖失败 |

- **判定依据是"现象"而非"分支方向"**：
  - `if (stockOk) { 保存 }` → 真分支 = 正常流程
  - `if (coupon == null) throw` → 真分支 = 异常流程
- **各类结构映射**：
  - 复合条件拆原子："成功 1 条" = 正常流程；"各原子不满足"各 1 条 = 异常流程
  - switch：各 case 分支 = 正常流程；default = 异常流程
  - 外部契约五态：成功有效 / 成功空值（代码处理为成功）= 正常流程；抛异常 / 超时 / 降级（代码拒绝）= 异常流程
  - 边界值：落在成功区的 = 正常流程；落在拒绝/失败区的 = 异常流程
- **硬性承诺**：每个功能**至少 1 条正常流程用例**（成功主路径）；若无，说明该功能正常路径未被覆盖，须显式补或说明原因（对应"功能级 100% 承诺"的既有约束）

### 3. 覆盖说明 sheet 新增「场景类型分布」

- 位置：与「可自动化程度分布」并列（其后）
- 内容：**按功能统计 正常流程 / 异常流程 用例数**，让"每个场景覆盖正常+异常"可核算、可核对
- 数据来源：`cases.json` 逐条统计 `scenario_type`

### 4. 字段质量自检扩展（8 → 9 条）

新增 1 条：**场景类型标注正确**——正常流程用例的预期结果须为成功完成（返回成功/状态变更成功），异常流程用例的预期结果须为拒绝/失败（抛异常/错误码）；两者不得互换。
