# code-scenario-testcases · 自测执行与收尾闭环优化设计

日期：2026-08-02
状态：已批准（用户四项优化范围全选）

## 1. 背景与目标

当前 skill（v1.17）产出的是「验证设计」——把业务代码梳理成 业务场景 → 功能 → 验证点 → 用例 四级结构并生成 Excel，覆盖了研发自测流程的**设计阶段**（需求理解、代码走读、用例设计、覆盖核对）。

对照一份完整的人工自测经验流程，skill 存在三处缺口：

| 自测流程阶段 | 当前覆盖 | 缺口 |
|---|---|---|
| 需求理解与范围界定 | 部分（有双基线） | "成功判据三问"与"改动范围/测试边界"界定未显式化 |
| 设计、覆盖核对 | ✅ | — |
| **自测执行与收尾**（冒烟先行、FAIL 闭环、需求偏差确认、回补用例、自测结论） | ❌ | 完全缺失——skill 到"生成 Excel"就止步 |
| 人工自测 8 列模板 | ❌ | 未内置，快速人工场景无模板可用 |

**目标**：将 skill 从「验证设计」扩展为「设计 + 执行收尾」完整自测链路，同时精简现有结构，消除重复，保持文档清晰。

## 2. 结构方案（已批准：三阶段重组）

```
阶段 0  前置界定   第 0 步  需求理解与范围界定        新增
阶段 1  验证设计   第 1~6 步（现第 1~6 步微调）       保留主体
阶段 2  执行收尾   第 7~8 步（汇报增强 + 执行闭环）   新增第 8 步，第 7 步增强
附录     人工自测 8 列模板                            新增
```

备选方案（未选）：增量式补丁——现有 7 步不动、仅追加第 8 步。改动小但结构臃肿未清，且与"精简"要求冲突。

## 3. 具体改动

### 3.1 第 0 步 · 需求理解与范围界定（新增）

插在现第 1 步之前，内容：

- **成功判据三问**：给谁用（角色/入口）、输入输出契约（入参/返回/状态码）、成功判据（验收标准中可判定的那句话）
- **范围界定**：本次改动范围（`-diff` 定位受影响函数 + grep 调用方）、**测试边界**（本功能职责 vs 外部依赖——外部依赖用 mock，不真测）
- 产出并入第 1 步双基线，作为"测什么"的起点依据

### 3.2 第 7 步 · 生成 Excel 与汇报（增强）

汇报新增：

- **自测结论**：`全部通过 / 阻塞项已修复 / 存在遗留缺陷 N 项（附清单）`，并明确**是否可提测**
- 风险提示补充**需求偏差项**（代码与需求不一致、待与产品/负责人确认的事项）

### 3.3 第 8 步 · 自测执行与收尾（新增，可选）

标注"可选——仅当本次需要执行闭环时启用，纯设计产出场景可跳过"。内容：

- **冒烟先行**：先跑 P0 主流程，主流程断了先修，不浪费时间测分支
- **FAIL 闭环**：`用例 FAIL → 定位原因 → 修复代码 → 重跑该条 → 重跑相邻用例`（防修复引入新问题）
- **需求偏差确认**：代码与需求对不上时**停下确认**，不擅自按自己理解测
- **回补用例**：把本次有价值场景回补进用例集，作为下次回归基线
- **收尾交付**：汇总统计（用例总数/PASS/FAIL/覆盖率）+ 遗留问题清单 + 自测结论（明确是否可提测）

### 3.4 附录 · 人工自测 8 列模板（新增）

- 提供 markdown 8 列模板（编号 / 用例名称 / 前置条件 / 操作步骤 / 预期结果 / 验证方法 / 优先级 / 结果）
- **触发条件**：用户只要快速人工自测、不需要 Excel 时直接输出该模板；生成 Excel 的完整流程不受影响

### 3.5 精简重排

- **流程总览表**更新为含「阶段划分」的新版本（8 步 + 附录）
- **合并重复**：验证方法、可自动化程度两处枚举定义只保留一处权威定义，其余引用——**权威定义落点在 14 列字段说明表的"验证方法 / 可自动化程度"两行**；第 3 步第 8/9 点改为引用该表，不重复枚举
- **压缩冗余**：14 列表格填写规则与 9 条字段自检的精简措辞，保留全部语义
- **README §2.5 同步**：工作流程从 7 阶段更新为 8 步 + 附录
