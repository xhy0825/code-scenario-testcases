# 典型业务规则缺口审查清单

代码驱动测试发现不了"该有却没有的分支"。**反向审查**（SKILL.md 第 5 步）：对每个功能逐条对照，规则在代码中找不到对应判定点时，标记"疑似规则缺口"——需与需求/产品确认该规则是否应存在。

## 通用规则清单

| 类别 | 典型规则 | 代码中应出现的判定点示例 |
|---|---|---|
| 金额 | 金额必须 > 0 / 非负 | `if (amount <= 0)` |
| 金额 | 单笔/单日金额上限 | `if (amount > MAX)` |
| 金额 | 折扣后金额不能为负 | `if (total < 0) total = 0` |
| 金额 | 金额精度/小数位 | `if (amount != round(amount, 2))` |
| 库存 | 库存不足拦截 | `if (!stock.check(...))` |
| 库存 | 超卖防护（扣减校验） | `if (stock.decrease() < 0)` |
| 权限 | 未登录/未授权拦截 | `if (user == null \|\| !hasRole(...))` |
| 权限 | 角色/状态校验 | `if (user.getRole() != ADMIN)` |
| 权限 | 越权访问（本人数据） | `if (resource.ownerId != currentUserId)` |
| 重复提交 | 幂等/防重 | `if (existsByBizId(...))` |
| 并发 | 并发修改防护/乐观锁 | `if (version != expected) throw` |
| 状态机 | 非法状态迁移拦截 | `if (order.getStatus() != PAID) throw` |
| 必填 | 必填参数校验 | `if (param == null \|\| param.isEmpty())` |
| 时效 | 过期/超时/有效期 | `if (expireAt < now)` |
| 数据 | 不存在/越界 | `if (findById(...) == null)` |
| 安全 | 敏感操作二次确认 | `if (!confirmed) throw` |
| 安全 | 敏感信息脱敏/加密 | `if (!isEncrypted) throw` |

## 审查输出格式

对每个功能逐条核对后，规则缺口写入 `coverage.rule_gaps`：

```
{"category": "权限", "function": "取消订单", "gap": "未校验操作人是否订单归属人", "confirm_with": "产品/需求"}
```

- 命中（代码有对应分支）→ 已覆盖，跳过
- 未命中 → 标记疑似缺口，标注 类别 / 功能 / 缺口描述 / 建议确认人
- **规则缺口不降低判定点覆盖率**，但单独列出——避免"100% 覆盖却缺关键规则"的错觉

## 使用提示

- 若调用时附带了**需求/契约**，以需求规则为准逐条核对，缺口即视为**疑似缺陷**
- 缺口清单是"提示"而非"结论"——某些规则可能由框架、上游系统、人工流程保障，确认后再决定是否补代码或补用例
