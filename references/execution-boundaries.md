# 执行边界清单（避免过度执行）

本清单定义 skill 在**扫描、识别、展开**时主动收敛的边界，防止生成与业务无关或用例爆炸的输出。SKILL.md 各步骤在遇到边界情况时按本文件处理。

## 1. 扫描边界（不纳入分析）

| 类别 | 排除示例 |
|---|---|
| 依赖库 / SDK | node_modules、vendor、.venv、site-packages、jar 等 |
| 测试文件 | `*_test.go`、`test_*.py`、`*Test.java`、`*.spec.ts` |
| 构建产物 | target、build、dist、bin、out |
| **生成代码** | `*_gen.go`、`*_generated.java`、`*.pb.go`、protobuf / OpenAPI / ORM 生成物 |
| **样板/无逻辑代码** | DTO/POJO/VO 纯数据类（仅字段 + getter/setter）、常量类、配置类 |
| **非代码文件** | 模板（jsp/thymeleaf/velocity）、配置文件（yaml/xml/properties）、SQL、文档 |

## 2. 功能入口边界（不作为"功能"）

- **private 方法**：只通过公开路径间接覆盖，不单独成为功能入口
- **纯工具函数**（`StringUtil.isEmpty`、`DateUtil` 等）：非业务入口，排除或仅标注
- **框架回调/钩子**（`run`、`onMessage`、序列化回调）：不视为业务入口
- **启动/初始化类**（`main`、`Application`、Bean 配置）：无业务判定，排除

## 3. 展开深度边界（防用例爆炸）

| 项 | 上限 | 超限处理 |
|---|---|---|
| 调用链深度 | 2-3 层 | 更深标注"深层调用不展开"，不递归 |
| 嵌套条件深度 | 5 层 | 超过不再拆内层组合，标注 |
| 复合条件原子数 | 5 个 | 超过合并或标注，不逐原子拆（2⁵ 组合会爆） |
| 单次用例数 | 100 条 | 超过提示用户聚焦模块/优先级 |
| 循环迭代 | 空/单/多 三种规模 | 不枚举每次迭代 |

## 4. 边界值边界

- 每个比较判定只补**标准边界**（等于边界、边界±1、null/空），不穷举所有取值
- 金额/数量/库存等高风险比较才额外给极值（MAX/MIN）

## 5. 规则缺口审查边界

- 规则缺口是**提示而非结论**：明显不适用场景（纯工具类、非业务代码）跳过
- 框架/上游系统保障的规则不误报为缺口（确认后再决定补代码或补用例）

## 6. 规模边界

- 目录源文件过多（> 50 个）时，优先分析用户指定的模块/入口，并在汇报中说明覆盖范围
- 多语言混合仓库：聚焦目标语言/模块，不跨语言混杂
