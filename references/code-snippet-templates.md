# 代码片段 → 测试用例模板 参考

**本文件是"每类条件结构怎么展开用例"的唯一权威**——SKILL.md 第 3 步只保留核心规则，展开细则以本文件为准。把各类条件结构的**代码片段**与其生成的**测试用例模板**一一对应；执行时把片段换成被测代码即可套用。示例以 Java 为主，语言差异已在"语言提示"注明（详见 `language-guide.md`）。

## 通用用例列（每张模板统一 11 列）

| 用例编号 | 业务场景 | 功能 | 用例名称 | 前置条件 | 操作步骤 | 优先级 | 预期结果 | 测试结果 | 备注 | 代码位置 |
|---|---|---|---|---|---|---|---|---|---|---|

用例编号占位符：`TC-<场景缩写>-<序号>`；业务场景/功能按实际聚合填写；测试结果列留空（下拉 PASS/FAIL）；代码位置填 `文件:行号`。

## 资深审查要点（角色定位落地）

套用模板时，以**资深研发自测架构师**身份额外自检，每个场景的高风险点见各场景"资深审查要点"行。通用原则：

1. **高风险优先**：金额、权限、安全校验、状态迁移、并发、空指针相关判定 → P0；边缘/兜底/边界 → P2
2. **判定为假的"成因"必须可区分**：复合条件写清楚是哪个原子不满足，别让研发猜
3. **外部依赖不硬编**：调用外部服务的分支，预期结果标"推断（需联调）"，并在覆盖说明 notes 标注
4. **代码隐患主动提示**：遇到可能 NPE、未判空、switch 传 null、浮点精度、资源未释放等，写入用例备注提醒
5. **每个用例可执行**：前置可构造、步骤可复现、预期可判定（错误码/文案/返回体）

## 场景 1：简单 if 校验（guard / 提前 return）

**代码片段：**
```java
if (req.getUserId() == null) {
    throw new BizException("用户不能为空");
}
```

**判定点：** 1 个。真分支 → 报错；假分支 → 继续。

**用例模板：**

| 用例编号 | 功能 | 用例名称 | 前置条件 | 操作步骤 | 优先级 | 预期结果 | 备注 |
|---|---|---|---|---|---|---|---|
| TC-001 | 创建订单 | 用户为空校验 | 调用创建订单接口 | body 传 {userId:null} | P0 | 返回错误"用户不能为空"，不生成订单 | 预期结果来源：代码摘录 |
| TC-002 | 创建订单 | 用户非空-正常 | userId 有效 | 正常传参 | P1 | 校验通过，继续执行后续逻辑 | 预期结果来源：推断 |

> 语言提示：Go 用 `if err != nil { return ... }`；Python 用 `if x is None: raise ...`；JS 用 `if (!user) throw ...`——结构相同，均按"真=拦截 / 假=放行"拆两条。

## 场景 3：if-else if-else 链（多路）

**代码片段：**
```java
if (amount > 1000) {
    level = "L3";
} else if (amount > 500) {
    level = "L2";
} else {
    level = "L1";
}
```

**判定点：** 每个 `if/else if` 各一个判定点；`else` 为兜底假分支。按执行顺序编号。

**用例模板：**

| 用例编号 | 功能 | 用例名称 | 前置条件 | 操作步骤 | 优先级 | 预期结果 | 备注 |
|---|---|---|---|---|---|---|---|
| TC-001 | 定级 | 金额>1000 | amount=1001 | 正常下单 | P1 | 等级置 L3 | 边界：1000/1001 |
| TC-002 | 定级 | 金额>500 | amount=501 | 正常下单 | P1 | 等级置 L2 | 边界：500/501 |
| TC-003 | 定级 | 兜底等级 | amount=100 | 正常下单 | P2 | 等级置 L1 | else 兜底分支 |

> 边界值（A2）会在相邻判定的临界值（1000/1001、500/501）补充边界用例。

## 场景 4：嵌套 if（外层+内层）

**代码片段：**
```java
if (req.getCouponId() != null) {                 // 外层
    Coupon coupon = couponService.getById(req.getCouponId());
    if (coupon == null) {                        // 内层
        throw new BizException("优惠券无效");
    } else if (coupon.getStatus() != CouponStatus.ACTIVE) {
        throw new BizException("优惠券已失效");
    }
}
```

**判定点：** 外层 1 + 内层 2。内层用例的**前置条件写入外层取值**（couponId != null），**不做笛卡尔积**。

**资深审查要点：** 内层只在外层成立时可达——前置条件必须写外层取值；防漏的是"外层真 + 内层各分支"组合，而非全笛卡尔积。

**用例模板：**

| 用例编号 | 功能 | 用例名称 | 前置条件 | 操作步骤 | 优先级 | 预期结果 | 备注 |
|---|---|---|---|---|---|---|---|
| TC-001 | 创建订单 | 不使用优惠券 | couponId=null | 不传 couponId | P1 | 跳过优惠券逻辑 | 外层假分支 |
| TC-002 | 创建订单 | 优惠券无效 | couponId!=null 且券不存在 | 传 {couponId:999} | P1 | 返回错误"优惠券无效" | 外层真+内层真；代码摘录 |
| TC-003 | 创建订单 | 优惠券已失效 | couponId!=null、券存在但非 ACTIVE | 传失效券 | P1 | 返回错误"优惠券已失效" | 外层真+内层 else-if 真 |
| TC-004 | 创建订单 | 优惠券有效 | couponId!=null、券存在且 ACTIVE | 传有效券 | P1 | 折扣置为券面额，下单成功 | 外层真+内层全假；推断 |

## 场景 5：switch / case / default

**代码片段：**
```java
switch (req.getPayType()) {
    case 1: order.setPayChannel("wechat");   break;
    case 2: order.setPayChannel("alipay");   break;
    case 3: order.setPayChannel("unionpay"); break;
    default: throw new BizException("支付方式不支持");
}
```

**判定点：** 每个 `case` 各一条 + `default` 一条。

**资深审查要点：** default 常是错误处理，别漏；case 合并仍各算一路；枚举新增取值时 default 兜底是否合理。

**用例模板：**

| 用例编号 | 功能 | 用例名称 | 前置条件 | 操作步骤 | 优先级 | 预期结果 | 备注 |
|---|---|---|---|---|---|---|---|
| TC-001 | 创建订单 | 微信支付 | 前置校验全过 | 传 payType=1 | P1 | payChannel=wechat | case 1；代码摘录 |
| TC-002 | 创建订单 | 支付宝支付 | 前置校验全过 | 传 payType=2 | P1 | payChannel=alipay | case 2 |
| TC-003 | 创建订单 | 银联支付 | 前置校验全过 | 传 payType=3 | P1 | payChannel=unionpay | case 3 |
| TC-004 | 创建订单 | 支付方式不支持 | 前置校验全过 | 传 payType=99 | P2 | 返回错误"支付方式不支持" | default；代码摘录 |

> 语言提示：Go `switch x { case 1: }`；Python 用 `match x: case 1:`；Rust `match x { 1 =>, _ => }`。case 合并（`case 1: case 2:`）仍各算一路。

## 场景 6：复合条件 && / ||（原子条件拆分）

**代码片段：**
```java
if (id == null || id <= 0) {                 // || 复合
    throw new BizException("订单ID不合法");
}
if (user != null && user.getStatus() == ACTIVE) {  // && 复合
    grantAccess();
}
```

**判定点：** 每个原子条件"不满足"各 1 条 + 成功路径 1 条（A1 规则），让判定为假的"成因"明确。

**资深审查要点：** 判定为假的成因可能有多个，必须分别覆盖每个原子；注意短路求值顺序（`&&` 左假则右不求值）。

**用例模板（以 `||` 为例）：**

| 用例编号 | 功能 | 用例名称 | 前置条件 | 操作步骤 | 优先级 | 预期结果 | 备注 |
|---|---|---|---|---|---|---|---|
| TC-001 | 查询订单 | id为空校验 | 调用查询接口 | 传 id=null | P0 | 返回错误"订单ID不合法" | 原子1(id==null)不满足 |
| TC-002 | 查询订单 | id非正数校验 | 调用查询接口 | 传 id=0 | P0 | 返回错误"订单ID不合法" | 原子2(id<=0)不满足；边界 |
| TC-003 | 查询订单 | id合法-正常 | id>0 | 正常查询 | P1 | 继续执行 | 成功路径 |

> 高安全场景（金额/权限/支付）可再按 MC/DC 展开：每个原子条件独立改变判定结果。

## 场景 8：循环内条件 + break / continue

**代码片段：**
```java
for (CartItem item : req.getCart()) {
    if (item.getQuantity() <= 0) {              // 循环内校验
        throw new BizException("商品数量不合法");
    }
    if (item.isSoldOut()) {                     // 循环内 continue
        continue;
    }
    total += item.getPrice() * item.getQuantity();
}
```

**判定点：** 循环内每个 `if` 真/假各一条；补充**空集合**边界用例。

**资深审查要点：** 空集合、单元素、多元素三种规模都要覆盖；break/continue 影响后续迭代；大循环注意性能类问题。

**用例模板：**

| 用例编号 | 功能 | 用例名称 | 前置条件 | 操作步骤 | 优先级 | 预期结果 | 备注 |
|---|---|---|---|---|---|---|---|
| TC-001 | 下单结算 | 数量不合法 | 购物车含 quantity<=0 | 提交订单 | P0 | 返回错误"商品数量不合法" | 循环内 if 真；代码摘录 |
| TC-002 | 下单结算 | 商品售罄跳过 | 购物车含售罄商品 | 提交订单 | P1 | 跳过该商品，其余累加 | 循环内 continue |
| TC-003 | 下单结算 | 正常累加 | 购物车含正常商品 | 提交订单 | P1 | total 正确累加 | 循环内条件全假 |
| TC-004 | 下单结算 | 空购物车 | 购物车为空 | 提交订单 | P2 | 返回错误"购物车为空" | 空集合边界 |

## 综合案例：下单结算（复合 + 循环 + 嵌套 组合展开）

真实业务通常是多种结构叠加，下面演示如何套用多个场景模板合并展开：

**代码片段（Python）：**
```python
def checkout(req):
    if req.cart is None or len(req.cart) == 0:          # 场景12 判空 + 场景6 复合
        raise HTTPException(400, "购物车为空")
    total = 0
    for item in req.cart:                               # 场景8 循环
        if item.quantity <= 0:                          # 场景9 边界
            raise HTTPException(400, "商品数量不合法")
        total += item.price * item.quantity
    if req.coupon_code:                                 # 场景4 嵌套外层
        coupon = get_coupon(req.coupon_code)
        if coupon is None:                              # 场景4 嵌套内层
            raise HTTPException(400, "优惠券不存在")
    return create_order(total)
```

**展开要点：**
1. 复合 + 判空 → 成功 1 条 + 每个原子不满足各 1 条（`cart=None`、`cart=[]`）
2. 循环内数量校验 → 真/假 + 边界（`quantity=0/1`）
3. 嵌套优惠券 → 外层真/假 + 内层真/假（内层用例前置条件写 `coupon_code` 非空，不笛卡尔积）
4. 空购物车、数量边界归 P2

**合并用例清单（节选）：**

| 用例编号 | 功能 | 用例名称 | 前置条件 | 操作步骤 | 优先级 | 预期结果 | 备注 |
|---|---|---|---|---|---|---|---|
| TC-001 | 下单结算 | 购物车为空对象 | 调用结算接口 | 传 cart=null | P0 | 400"购物车为空" | 复合原子1(null)；代码摘录 |

## 使用指引

1. 从被测代码中找到片段 → 对照上表定位**场景类型**（可叠加：嵌套+复合+边界、循环+判空等）
2. 套用该场景的用例模板，把片段变量换成被测代码的实际取值
3. 多结构叠加时，按 SKILL.md 第 3 步"嵌套不笛卡尔积、复合拆原子、边界补值"合并展开
4. 最后统一补 业务场景/功能/代码位置/优先级，并做第 4 步机器枚举核对
